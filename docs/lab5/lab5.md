# ЛР5. Тестирование REST API с помощью Postman и Python

Объект тестирования: публичное REST API JSONPlaceholder (https://jsonplaceholder.typicode.com), ресурс `/users`. По условию ЛР5 приложение не пишется самостоятельно.

Почему JSONPlaceholder, а не reqres.in: reqres.in в 2025 году вводил обязательный API-ключ, его поведение менялось. JSONPlaceholder работает без ключа и стабилен, что важно для запуска тестов в CI (ЛР9).

Особенность API: JSONPlaceholder имитирует запись — POST и PUT возвращают корректный ответ, но данные на сервере не меняются. Поэтому проверяется ответ сервера, а не последующее чтение.

## 1. Коллекция Postman (ручное задание)

Файл `postman/lab5.postman_collection.json` (импорт: Postman → Import → выбрать файл). Адрес API вынесен в переменную коллекции `baseUrl`.

| № | Запрос | Что проверяют тесты (JavaScript) |
|---|--------|----------------------------------|
| 1 | `GET {{baseUrl}}/users/1` — получить пользователя | статус 200; ответ в JSON; время ответа < 2000 мс; структура по JSON-схеме (обязательные поля и их типы); значения `id`, `name`, `email` |
| 2 | `POST {{baseUrl}}/users` — создать пользователя | статус 201; есть числовой `id`; `name`, `username`, `email` совпадают с отправленными |
| 3 | `PUT {{baseUrl}}/users/1` — обновить пользователя | статус 200; структура по схеме; ответ совпадает с отправленным телом |
| 4 | `GET {{baseUrl}}/users/9999` — негативный, несуществующий пользователь | статус 404; тело — пустой объект `{}` |

Пример теста (запрос 1):

```javascript
pm.test('Статус 200', () => pm.response.to.have.status(200));
pm.test('Структура JSON соответствует схеме', () => pm.response.to.have.jsonSchema(schema));
pm.test('Значения полей', () => {
  const user = pm.response.json();
  pm.expect(user.id).to.eql(1);
  pm.expect(user.name).to.eql('Leanne Graham');
});
```

### Запуск коллекции (Collection Run)

В Postman: коллекция → Run → Run collection. Скриншот результата Runner вставить в отчёт.

Тот же прогон выполнен из командной строки через Newman (консольный запускатель коллекций Postman), полный вывод в `newman_output.txt`:

```
npx newman run postman/lab5.postman_collection.json
```

|---|---|---|
| Запросы | 4 | 0 |
| Тестовые скрипты | 4 | 0 |
| Проверки (assertions) | 13 | 0 |

Среднее время ответа 177 мс (от 84 до 276 мс).

### Анализ результатов
- Все 13 проверок прошли: API возвращает ожидаемые коды (200, 201, 404), структуру и значения.
- Негативный запрос подтверждает корректную обработку отсутствующего ресурса: 404 и пустой объект, без ошибки сервера (5xx).
- Время ответа стабильно меньше 300 мс, порог 2000 мс выполняется с запасом.
- Ограничение: API не сохраняет созданные и изменённые данные, поэтому сценарий «создал → прочитал» на нём проверить нельзя.

## 2. Автотесты на Python (requests + pytest)

Файл `tests/test_api.py` повторяет логику коллекции:

| Тест | Запрос Postman |
|------|----------------|
| `test_get_user` | 1 (статус, Content-Type, время, типы полей, значения) |
| `test_create_user` | 2 |
| `test_update_user` | 3 |
| `test_get_missing_user` | 4 |

Запуск:

```
.venv\Scripts\python -m pytest tests/test_api.py -v
```

Результат 21.10.2026: **4 passed** (полный вывод в `pytest_output.txt`).
