# ЛР1. Тест-план: калькулятор

## 1. Цель
Проверить, что калькулятор учебного стенда соответствует требованиям `requirements.md` (ТР-1…ТР-10): корректно выполняет арифметические операции, обрабатывает ошибочный ввод и очищает поля.

## 2. Объект тестирования
Страница `/calc` учебного стенда (Flask), запускается локально: `.venv/Scripts/python app.py`, адрес http://127.0.0.1:5000/calc.

## 3. Объём тестирования
**Входит:**
- четыре арифметические операции (ТР-1);
- элементы интерфейса (ТР-2);
- форматы ввода чисел, включая запятую и пробелы (ТР-3);
- граничные значения диапазона (ТР-4);
- точность и округление результата (ТР-5);
- сообщения об ошибках (ТР-6…ТР-8);
- сохранение введённых данных и очистка кнопкой «C» (ТР-9, ТР-10).

**Не входит:**
- нагрузочное тестирование (ЛР8), автотесты (ЛР3, ЛР4, ЛР6);
- безопасность, кроссбраузерность, мобильная вёрстка;
- остальные страницы стенда.

## 4. Стратегия
- Вид тестирования: ручное функциональное тестирование чёрного ящика.
- Уровни: смоук-проверка (страница открывается, 2 + 3 = 5), затем полный прогон чек-листа и тест-кейсов.
- Техники тест-дизайна:
  - **классы эквивалентности** для поля числа: целое; десятичное с точкой; десятичное с запятой; отрицательное; пустое; буквы; недопустимая запись (`+5`, `.5`, `5.`, `1e5`); вне диапазона;
  - **граничные значения** диапазона: -1000000001, -1000000000, 1000000000, 1000000001; для делителя — 0;
  - **предугадывание ошибок**: 0,1 + 0,2 (ошибки двоичной арифметики), 0 ÷ 0, -0, умножение двух максимальных чисел (потеря точности).
- Позитивные и негативные сценарии оформляются тест-кейсами (`test_cases.md`), остальные проверки — чек-листом (`checklist.md`).

## 5. Окружение
- Windows 11 Pro, Firefox 156;
- Python 3.13, Flask 3.1 (стенд запущен локально).

## 6. Критерии начала и окончания
- **Начало:** стенд запускается, страница `/calc` открывается, требования согласованы.
- **Окончание:** выполнены все пункты чек-листа и все тест-кейсы, по каждой проваленной проверке зафиксирован дефект.

## 7. Риски
| Риск | Влияние | Что делаем |
|------|---------|------------|
| Требования неполные или трактуются по-разному (например, формат вывода дробей) | Неверные ожидаемые результаты | Требования зафиксированы в `requirements.md` до начала тестирования |
| Ошибки округления вещественных чисел | Неверный результат на «неудобных» числах | Отдельные проверки на 0,1 + 0,2, деление с бесконечной дробью, максимальные значения |
| Поведение зависит от браузера (автозаполнение, локаль) | Невоспроизводимые результаты | Фиксируем окружение, при сомнениях проверяем во втором браузере |
| Нехватка времени | Неполное покрытие | Сначала тест-кейсы с высоким приоритетом |

## 8. Результаты (артефакты)
- `requirements.md` — требования;
- `test_plan.md` — этот документ;
- `checklist.md` — чек-лист с результатами прогона;
- `test_cases.md` — тест-кейсы с фактическими результатами.
