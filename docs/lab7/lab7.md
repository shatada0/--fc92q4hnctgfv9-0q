# ЛР7. Тестирование мобильного приложения

Объект тестирования: собственное Android-приложение «Заметки» (`mobile/`). Возможности:
- поле ввода и кнопка «Добавить» — добавление заметки (пустой текст и пробелы не принимаются, поле подсвечивается ошибкой);
- список заметок с прокруткой, счётчик «Заметок: N»;
- удаление заметки долгим нажатием (с всплывающим сообщением «Заметка удалена»);
- хранение заметок в `SharedPreferences`: они сохраняются после закрытия приложения.

Код: `mobile/app/src/main/java/com/example/notes/MainActivity.java`, разметка `mobile/app/src/main/res/layout/activity_main.xml`, манифест `mobile/app/src/main/AndroidManifest.xml`. Язык Java, без сторонних библиотек.

Сборка APK:

```
cd mobile
gradlew assembleDebug        →  app/build/outputs/apk/debug/app-debug.apk
```

Особенность: путь проекта содержит кириллицу («тестпо»), Android Gradle Plugin на Windows такие пути по умолчанию не принимает. В `mobile/gradle.properties` добавлен флаг `android.overridePathCheck=true`.

Окружение: Windows 11, эмулятор Android Pixel 10a (`Pixel_10a`, Android API 37), Android Studio 2026.1 (JDK 25 из её состава), Gradle 9.7.1, Android Gradle Plugin 9.4.1.

### Найденный дефект

**Дефект 1. Содержимое экрана прижато к краям, заданные отступы не применяются.**
- Шаги: запустить приложение, добавить заметку.
- Ожидаемый результат: отступ 16 dp от краёв экрана (задан `android:padding="16dp"` в разметке).
- Фактический результат: поле ввода, счётчик и текст заметок начинаются вплотную от левого края (`screenshots/01_start.png`).
- Причина: у корневого контейнера одновременно заданы `android:fitsSystemWindows="true"` и `android:padding`. Атрибут `fitsSystemWindows` заменяет отступы контейнера на размеры системных панелей, поэтому собственный `padding` теряется.
- Severity: Trivial, Priority: Low. Окружение: эмулятор Pixel 10a, API 37.

### Замечания
1. Текст на кнопке задан как «Добавить», а отображается «ДОБАВИТЬ»: тема Material по умолчанию пишет текст кнопок заглавными буквами. Это ожидаемое поведение темы, а не дефект, но тесты, сравнивающие текст кнопки, должны это учитывать.
2. Недописанный текст в поле ввода теряется после принудительного завершения процесса (п. 16), при этом сохранённые заметки на месте. Это стандартное поведение Android: при `force-stop` сохранённое состояние экрана удаляется. При обычном уничтожении activity системой (п. 15) черновик восстанавливается.

## 2. Автоматизация с Appium (автоматическое задание)

### Установка и настройка окружения

```
npm install -g appium                  # Appium 3.7.0
appium driver install uiautomator2     # драйвер UiAutomator2 8.7.0
appium driver doctor uiautomator2      # проверка окружения: 0 обязательных исправлений
pip install Appium-Python-Client       # 6.0.7 (есть в requirements.txt)
```

Переменные окружения: `ANDROID_HOME = %LOCALAPPDATA%\Android\Sdk`, `JAVA_HOME = C:\Program Files\Android\Android Studio\jbr`; в `PATH` добавлены `Sdk\platform-tools` (adb) и `Sdk\emulator`.

### Скрипт

Файл `mobile/test_notes.py`. Как и в Selenium WebDriver, тест создаёт удалённый драйвер (`webdriver.Remote` к серверу Appium `http://127.0.0.1:4723`), передаёт настройки (capabilities: платформа Android, драйвер UiAutomator2, путь к APK) и ищет элементы по локаторам. Appium сам устанавливает APK на эмулятор и запускает приложение.

Действия теста: ввод «Купить хлеб» в поле `noteInput`, **тап по кнопке `addButton`**, проверка, что в списке появилась заметка и счётчик показывает «Заметок: 1». Элементы ищутся по `resource-id` (`com.example.notes:id/...`) — аналог `id` в веб-странице.

Запуск:

```
emulator -avd Pixel_10a
appium
.venv\Scripts\python -m pytest mobile/test_notes.py -v
```

Результат 21.10.2026: **1 passed** (вывод в `pytest_output.txt`).

Мобильный тест лежит вне папки `tests/`, поэтому в CI (ЛР9) не запускается: там нет эмулятора.
