# ЛР3. Первые автотесты на Python + Selenium WebDriver

Объект тестирования: страница входа учебного стенда (`/login`, после входа `/home`). Код страницы: `app.py` (маршруты `login`, `home`, `logout`), `templates/login.html`, `templates/home.html`. Учётная запись стенда: `student` / `Passw0rd!`.

## 1. Окружение

| Компонент | Версия |
|-----------|--------|
| Windows 11 Pro | 10.0.26300 |
| Python | 3.13.15 |
| pip | 26.x |
| selenium | 4.49.0 |
| webdriver-manager | 4.1.2 |
| pytest | 9.1.1 |
| Firefox | 156.0.1 |
| geckodriver (скачан webdriver-manager) | 0.37.1 |

Установка:

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

Особенность окружения: Firefox установлен только для текущего пользователя (`%LOCALAPPDATA%\Mozilla Firefox`), а не в Program Files. geckodriver такую установку сам не находит и падает с ошибкой `Expected browser binary location, but unable to find binary in default location`. Поэтому путь к `firefox.exe` задан в переменной окружения `FIREFOX_BIN` и передаётся через `options.binary_location`.

## 2. Скрипт: открыть и закрыть браузер

Файл `scripts/open_browser.py`: создаёт драйвер Firefox (geckodriver скачивает `GeckoDriverManager`), открывает страницу входа, печатает адрес и заголовок, закрывает браузер. Закрытие стоит в `finally`, поэтому браузер закрывается даже при ошибке.

Запуск (стенд должен быть запущен командой `.venv\Scripts\python app.py`):

```
.venv\Scripts\python scripts\open_browser.py
```

Результат:

```
Открыта страница: http://127.0.0.1:5000/login | заголовок: Вход — учебный стенд
Браузер закрыт
```

## 3. Автотест входа

Файл `tests/test_login.py`, фикстуры в `tests/conftest.py`:
- `base_url` поднимает стенд в фоновом потоке на свободном порту, поэтому отдельно запускать его не нужно;
- `driver` создаёт Firefox через `GeckoDriverManager` и закрывает его после теста.

Тесты:
- `test_login_valid_credentials`: ввод валидных данных, нажатие «Войти», явное ожидание (`WebDriverWait`) появления элемента `#logout` с текстом «Logout», проверка адреса `/home`;
- `test_login_wrong_password` (дополнительно, негативный): неверный пароль, ожидание сообщения «Неверный логин или пароль», элемента «Logout» на странице нет.

Запуск:

```
.venv\Scripts\python -m pytest tests/test_login.py -v
```

Результат прогона 21.10.2026:

```
tests/test_login.py::test_login_valid_credentials PASSED                 [ 50%]
tests/test_login.py::test_login_wrong_password PASSED                    [100%]
============================= 2 passed in 11.66s ==============================
```

## 4. Анализ селекторов (ручное задание)

Оценивалась устойчивость: изменится ли селектор при правке дизайна, текстов или порядка элементов.

| Элемент | id | name | Рекомендуемый селектор | Стабильность | Комментарий |
|---------|----|------|------------------------|--------------|-------------|
| Поле «Логин» | `username` | `username` | `By.ID, "username"` | высокая | Уникальный id, не зависит от вёрстки и текста |
| Поле «Пароль» | `password` | `password` | `By.ID, "password"` | высокая | То же; запасной вариант `input[name="password"]` |
| Кнопка «Войти» | `login-btn` | — | `By.ID, "login-btn"` | высокая | У кнопки нет `name`, но есть id |
| Сообщение об ошибке | `login-error` | — | `By.ID, "login-error"` | высокая | Появляется только после неудачного входа, нужен явный wait |
| Ссылка «Logout» (`/home`) | `logout` | — | `By.ID, "logout"` | высокая | Главный признак успешного входа |
| Подписи полей (label) | — | — | `label[for="username"]` | средняя | Привязаны к полям атрибутом `for`, id нет |
| Заголовок «Вход» | — | — | `By.TAG_NAME, "h1"` | средняя | Единственный h1 на странице, но без id; проверка по тексту зависит от формулировки |
| Ссылки меню | — | — | `a[href="/login"]` | средняя | Адрес меняется реже текста, но id нет |
| Приветствие на `/home` | — | — | `By.TAG_NAME, "h1"` | низкая для проверки текста | Текст содержит имя пользователя («Привет, student!») |

Примеры неустойчивых селекторов, которых стоит избегать:

| Селектор | Почему плохой |
|----------|---------------|
| `/html/body/form/input[1]` | Абсолютный позиционный XPath ломается при добавлении любого элемента выше по странице |
| `//button[text()='Войти']` | Ломается при смене текста кнопки или переводе интерфейса |
| `form > input:nth-of-type(2)` | Зависит от порядка полей в форме |
| `nav a:nth-child(3)` | Ломается при добавлении пункта меню |

Вывод: все элементы, с которыми работает автотест (поля, кнопка, ошибка, Logout), имеют уникальные `id`, их и используем. Для элементов без id (заголовки, подписи, меню) лучше добавить `id` или `data-testid`, если они понадобятся в тестах.
