# ЛР4. Автоматизация позитивных и негативных UI-сценариев (Page Object)

Объект тестирования: форма «Обратная связь» учебного стенда (`/contact`). Код формы: `app.py` (маршрут `contact`), `templates/contact.html`.

## 1. Правила формы

| Поле | Обязательное | Правило | Текст ошибки |
|------|--------------|---------|--------------|
| Имя | да | не пустое (пробелы не считаются) | «Введите имя» |
| Email | да | не пустой; формат `имя@домен.зона` без пробелов | «Введите email» / «Некорректный email» |
| Телефон | нет | если заполнен: необязательный `+` и 10–15 цифр подряд | «Некорректный телефон» |
| Тема | — | выбор из списка: Вопрос, Предложение, Жалоба | — |
| Сообщение | да | не пустое | «Введите сообщение» |
| Согласие | да | флажок отмечен | «Нужно согласие на обработку данных» |

При успешной отправке выводится «Спасибо! Сообщение отправлено.», форма очищается. Ошибки показываются сразу по всем неверным полям. Проверка выполняется на сервере (`novalidate` у формы): встроенные подсказки браузера не являются частью страницы и зависят от языка браузера, проверять их текст в тестах неудобно.

## 2. Матрица (таблица) принятия решений — ручное задание

Условия по обязательным полям: Д — значение валидно, Н — невалидно (пусто; для email также неверный формат). Четыре условия дают 2⁴ = 16 правил. Необязательное поле «Телефон» на остальные поля не влияет, поэтому разобрано отдельно (п. 2.2), иначе таблица выросла бы втрое.

Все 16 правил проверены запросами к стенду, поведение совпало с ожидаемым.

## 3. Page Object

- `tests/pages/base_page.py`, класс `BasePage`: общие действия (`open`, `find` с явным ожиданием, `is_present`, `click`, `type`, `text`). Адрес страницы задаётся атрибутом `path` в наследнике.
- `tests/pages/contact_page.py`, класс `ContactPage(BasePage)`: локаторы полей (все по `id`) и действия со страницей: `fill(...)`, `submit()` (ждёт перезагрузки страницы после отправки), `success_text()`, `has_success()`, `error_text(field)`.

Тесты работают только через методы страницы и не содержат локаторов. При изменении вёрстки правится один класс, а не каждый тест.

## 4. Автотесты

Файл `tests/test_contact.py`, фикстуры `driver` и `base_url` из `tests/conftest.py` (как в ЛР3).

- **Позитивный** `test_submit_valid_form` (правило R01): заполнение всех полей валидными данными, отправка, проверка текста «Спасибо! Сообщение отправлено.» и отсутствия ошибок.
- **Негативный** `test_invalid_field_shows_error`, параметризован по шести случаям: пустые обязательные поля (`empty_name`, `empty_email`, `empty_message`), неотмеченное согласие (`no_consent`), неверный формат email (`bad_email`) и телефона (`bad_phone`). Остальные поля заполнены валидно. Проверяется текст ошибки у нужного поля и отсутствие сообщения об успешной отправке.

Запуск:

```
.venv\Scripts\python -m pytest tests/test_contact.py -v
```
